# A verifier's axioms have a symmetry group, and it is the set of wrong kernels its certificates cannot exclude: Why3's real theories, audited

**Date:** 2026-10-02
**Instance:** Apple M4 Pro, macOS 26.6.1, CPU only
**Toolchains:** Lean 4 v4.33.0 core, no Mathlib (`~/.elan/toolchains/leanprover--lean4---v4.33.0/bin/lean`);
Python 3.10.20 / NumPy 1.26.4 (the repo's pinned venv)
**Artifacts:** `proofs/why3-real-theories/Why3RealTheories.lean` (nine audited theorems, ~430 lines,
compiles in about one second; pinned by `tests/proofs/test_why3_real_theories_lean.py`, marker
`formal`); `experiments/formal-rigidity/rigidity.py` (the sampled audit; pinned by
`experiments/formal-rigidity/test_rigidity.py`, 11 tests)
**Source audited:** Why3's standard library as published at https://www.why3.org/stdlib/real.html,
generated by why3doc 1.8.2 — modules `ExpLog`, `Square`, `Trigonometry`, every axiom transcribed
one-to-one (see §1)
**Companions:** `2026-10-01-softmax-bundle-mechanized.md` §3 (the three-axiom version of this
finding), `2026-10-01-softmax-temperature-blind-spot.md` (what the admitted family does in the
gate and in the loop)

**Headline.** The pre-registered pilot predicted that an SMT-backed language which must
axiomatize `exp` "proves temperature-blind theorems unless a tangent-type axiom is assumed". Here
that prediction is checked, before any agent runs, against the one axiomatization of `exp` that
ships with a deployed verifier: Why3's `real.ExpLog`, the theory Frama-C/WP and SPARK/GNATprove
reason from. **All ten of its axioms hold for `x ↦ exp(βx)`, with `log` rescaled to `log(y)/β`,
for every β > 0** — machine-checked over an abstract ordered field. So a Why3 proof that code
"computes softmax with respect to `exp`" is, as a formal statement, equally a proof about
softmax(βx) for every β > 0: the theory fixes the *direction* of the exponential (β ≤ 0 is
excluded) and nothing about its *rate*. The same audit finds that `real.Square` is categorical
on x ≥ 0 (a layernorm certificate cannot be read as one for −LN) and that `real.Trigonometry`
has a *discrete* symmetry — `(cos(5x), sin(5x), atan(x)/5)` satisfies all sixteen axioms — so a
rotary-embedding kernel certified against it could rotate at five times the frequency. One
first-order axiom (`1 + x ≤ exp x`), or double-precision bounds on `e` in the style Why3 already
uses for π, removes the exponential family exactly. A sampling audit reproduces every verdict in
under two seconds per theory and, as a by-product, shows that the certificate design's check C6
as built would reject four of Why3's own trigonometric axioms as false.

## 2. The result

### 2.1 Proved (Lean), and reproduced by sampling

| theory | theorem | statement | sampled audit agrees |
|---|---|---|---|
| ExpLog | `why3ExpLog_scaled` | all ten axioms hold for `(x ↦ exp(βx), y ↦ log y / β)`, every β > 0 | `exp(2x)`, `exp(x/2)` ADMITTED |
| ExpLog | `why3ExpLog_rejects_nonpos` | β ≤ 0 is excluded: β = 0 by `Log_exp`, β < 0 by `exp_increasing` | `exp(0x)` rejected by `Log_exp`; `exp(−x)` rejected by `exp_increasing` |
| ExpLog | `softmaxRowWith_scaleExp` | softmax w.r.t. the rescaled `exp` is softmax at inverse temperature β | — (definitional) |
| ExpLog | `certificate_is_a_family` | any theorem derived from the axioms about `(exp, log)` holds of their rescaling | — (schema) |
| ExpLog | `value_pins` | an axiom fixing `exp` at one non-zero point forces β = 1 | — |
| ExpLog | `tangent_rigid` | `1 + x ≤ exp x` for `exp` and its rescaling forces β = 1 (uses only `exp_positive`, `Exp_sum`) | ExpLog + tangent: only identity ADMITTED; `exp(2x)` rejected by `Tangent` |
| Square | `why3Square_categorical` | any two models agree on x ≥ 0 | only identity ADMITTED; `−sqrt` rejected by `Sqrt_positive` |
| Trigonometry | `why3Trig_scaled_five` | `(cos(5x), sin(5x), atan(x)/5)`, same π, satisfies all sixteen axioms | `cos,sin(5x)` and `cos,sin(−3x)` ADMITTED |
| Trigonometry | `why3Trig_rejects_two` | rescaling by 2 breaks `Cos_pi` | `cos,sin(2x)` rejected by `Cos_pi`; `3x` rejected by `Sin_pi2` |

The sampled audit also checks a reinterpretation the Lean file does not state: double-precision
bounds on `e` (the two adjacent doubles around 2.718281828459045, after Why3's own
`Pi_double_precision_bounds`) reject `exp(2x)` and `exp(x/2)` — a one-line stdlib fix in the
style the library already uses.

Timing: 0.25–2.8 s per theory for the full sampled audit (4096 samples × up to 16 axioms × up to
7 reinterpretations); the Lean file compiles in about a second.

### 2.2 Reading the symmetry groups as kernel families

| primitive | Why3 theory's symmetry | the kernel family a certificate cannot exclude | does the test bundle admit it? |
|---|---|---|---|
| `exp`, `log` | continuous: β > 0 | softmax(βx), the temperature family; `softmax_exp2` and reciprocal-multiply rewrites sit inside it at β = 1 | yes — exactly the family of `2026-10-01-softmax-temperature-blind-spot.md`, minus β ≤ 0 |
| `sqrt` | trivial on x ≥ 0 | none: layernorm's `sqrt(var + eps)` is pinned, so −LN is excluded | the test bundle admits −LN; the Why3 axioms do not |
| `cos`, `sin`, `atan` | discrete: β ≡ 1 (mod 4) (witness 5, and −3) | rotary embeddings at frequency 5θ, −3θ, 9θ, … | not a task here |

Two comparisons with the paper's three-axiom theory (`ExpLaws`: positive, additive, injective):
Why3's theory is **strictly more rigid** — `exp_increasing` excludes β < 0, so the
ranking-reversed softmax(−x) and (via `Log_exp`) the uniform 1/n are outside it — and **still
temperature-blind**. The two wrong kernels it keeps, softmax(2x) and softmax(x/2), are the two
the training loop could not see either (`val_bpb` 2.2279 vs 2.2292, a tie), because a learned
query projection absorbs the factor. The one kernel the loop *does* reject on merit, the constant
fill, is also the one Why3's axioms reject.

## 3. Why it matters for agent-written certificates

The pre-registered design (§4 of `2026-10-01-agent-formal-adherence-design.md`) lets the agent
write the spec and prove adherence in SMT-backed languages where `exp` "exists only as axioms".
In Why3 it exists as *these* axioms; in Dafny, Verus and F* it exists as whatever the agent
writes, and the natural things to write are a subset of these. The present result turns the
pilot's prediction into a protocol item with a known answer: **a certificate whose spec names
`exp` and whose proof uses only `ExpLog` has, as formal content, "the kernel is softmax at some
β > 0"**. Only three things can say which β: an axiom outside the symmetry group (`Tangent`,
bounds on `e`, or any single value — `value_pins`), the executable reading (checks C2–C4, which
bind `exp` to `np.exp`), or the kernel's own use of a library `exp` whose contract is trusted.

The audit tool is the C6′ the positioning review asked for: given an attempt's axiom readings,
it reports which reinterpretations of the primitives survive — i.e., which wrong kernels the
proof is also a proof about — and attributes each rejection to one axiom. It runs in
milliseconds per reinterpretation and needs nothing the design does not already collect.

## 4. An instrument finding, found by the audit itself

`formal.checks._axioms` compares each axiom's two sides through `Comparisons.close`, which
divides the residual by max|expected| and falls back to a unit scale only when that is *exactly*
zero. An identity whose two sides pass *near* zero is therefore rejected on the true primitives:
the rounding of a value of size 1e-12 is about 1e-28, but the comparison demands 1e-12 · ε.
Measured on the true `exp`, `log`, `cos`, `sin` with the harness's raw comparison, fraction of
4096 samples rejected:

| theory | axiom | false-rejection rate |
|---|---|---|
| ExpLog | `Log_exp` (log(exp x) = x, near x = 0) | 0.002 |
| ExpLog | `Log_mul` (near x·y = 1) | < 0.0005, non-zero |
| Trigonometry | `Sin_plus_pi` | 0.024 |
| Trigonometry | `Cos_plus_pi2` | 0.008 |
| Trigonometry | `Sin_sum` | 0.004 |
| Trigonometry | `Cos_sum` | 0.002 |

At 4096 samples any of these is a certain C6 failure for a true axiom. The audit uses the standard
mixed tolerance instead — absolute in units of ε below |expected| = 1, relative above
(`FlooredComparisons`) — under which every true axiom of every theory passes on every sample
(`test_the_floored_comparison_accepts_every_true_axiom`). The design should adopt the floor for
C6, or require axioms to be stated with one side bounded away from zero. This is the fourth time
in this project a comparison has been found to model the wrong error term (CLAUDE.md, "a
property's tolerance must model the dominant error mechanism"), and the first time in the formal
track.

A second limit of sampling, also measured: a true trigonometric symmetry at β = 9 is rejected on
[−5, 5] and at β = 5 on the same range, because the float argument β(x + y) reaches ~37 and its
ulp (7e-15) passes straight into the value. The audit samples trigonometric axioms on [−1, 1]
and lists only β ∈ {5, −3}; the Lean statement is exact and range-free.

## 5. Threats to validity

- **One version, one source.** The axioms are those of why3doc 1.8.2 as published on why3.org;
  the gitlab source was not reachable from here (bot protection), and an AdaCore mirror returned
  the same axiom *names*. A future stdlib may add a pinning axiom, and should.
- **Frama-C/WP: confirmed; SPARK: not audited.** WP's own theory for ACSL's real functions,
  `src/plugins/wp/share/why3/frama_c_wp/cmath.mlw`, reads `use real.ExpLog`, `use real.Square`
  and `use real.Trigonometry as Trigo`, and adds one axiom about `exp` (`exp_pos`, already
  implied by `exp_positive`), three lemmas about `sqrt` and two about `asin`/`acos` — none of
  which constrains the rate of `exp`, so WP inherits the symmetry exactly. SPARK/GNATprove's
  `Ada.Numerics` models were not read and may add or replace axioms; the tool is built to audit
  them.
- **Abstract ordered field, not ℝ.** Every theorem is stronger than its ℝ instance in one sense
  (it holds in every model) and says nothing in another: `why3Square_categorical` does not say
  the axioms *have* a model over a given field, only that any two agree.
- **Sampling confirms a symmetry only on the sampled points**, within a float budget whose reach
  is bounded by argument conditioning (§4). Every sampled verdict here has a Lean counterpart or a
  one-axiom attribution; the sampled audit is the cheap, language-neutral instrument, not the
  proof.
- **The kernel-family reading of the trigonometric symmetry is a remark**, not a measured
  kernel: no rotary-embedding task exists in this repo.

## 6. What is NOT claimed

- **Not that Why3 proofs are wrong.** Every theorem Why3 accepts from `ExpLog` is true in every
  model, the real exponential included. The claim is about what the *spec* "softmax w.r.t.
  `exp`" denotes when `exp` is given only these axioms: a family, not a function.
- **Not that a Why3 user who binds `exp` to a trusted library contract is affected.** The
  temperature then lives in the library's contract, which is where it should live. The affected
  setting is the one the pilot studies: an agent that writes the spec, chooses the primitives and
  axiomatizes them itself — or a kernel that implements its own exponential.
- **Not a detection rate**, and not a property of SMT solvers: it is a property of the axiom set,
  and an ITP that *defines* `exp` (Lean with Mathlib, Rocq, Isabelle/HOL) has no such symmetry.
- **Not that `Tangent` characterizes `exp`**: it pins β among rescalings; other models of the
  axioms exist over non-Archimedean fields.

## 7. What the pilot inherits

- A registered answer for the Why3 cell of E1 before it runs: any attempt whose axioms are a
  subset of `ExpLog` is temperature-blind as a formal statement; the audit will say so per attempt.
- C6′, implemented and pinned, ready to be specified as a feature under `src/autokernel_pbt/formal/`
  (it needs an `Axiom.holds_on` reading, which attempts already carry, plus a transformation
  library per primitive).
- A one-line recommendation to the Why3 maintainers, in their own idiom: give `ExpLog` the
  bounds on `e` that `Trigonometry` gives π.
- The C6 comparison floor (§4), to adopt before the first agent attempt is judged.
